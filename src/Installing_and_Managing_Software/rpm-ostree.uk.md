# Накладання пакетів

## Використання `rpm-ostree` { #using-rpm-ostree }

!!! attention

    Необачне накладання пакетів може бути **руйнівним**: воно може блокувати оновлення й спричиняти інші проблеми, доки накладені пакети не буде видалено.

Встановлюйте [пакети Fedora Linux](https://packages.fedoraproject.org/) поверх наявного образу Bazzite командою `rpm-ostree` у терміналі. Робіть це для пакетів, які не можна встановити з Homebrew або запустити в контейнері. Через проблеми із залежностями накладені пакети можуть ламати оновлення системи, доки їх не видалити, бо пакет доводиться оновлювати разом з рештою образу. Також через них оновлення триває довше.

### Головне { #key-notes }

- Після накладання пакетів **потрібно** перезавантажити систему, коли буде створено нове розгортання з доданими до образу пакетами.
- Використовуйте цей спосіб **лише в крайньому разі** і тільки для того, що працює «на рівні системи», бо він може призупинити оновлення, якщо пакет матиме проблеми із залежностями в майбутніх оновленнях, доки пакет не буде видалено.

## Команди для накладання пакетів { #terminal-commands-related-to-package-layering }

**Використовуйте ці команди на власний ризик**.

### Накладання пакетів { #layer-packages }

```
rpm-ostree install <package>
```

Встановлює в систему пакети Fedora, які зберігаються між оновленнями. Щоб застосувати встановлення, перезавантажте систему.

### Видалення накладених пакетів { #uninstall-layered-packages }

```
rpm-ostree uninstall <package>
```

Видаляє будь-які накладені в системі пакети. Щоб застосувати видалення, перезавантажте систему.

### Пошук пакета { #search-for-a-package }

```
rpm-ostree search <package>
```

Шукає пакети Fedora, які можна встановити.

### Перегляд накладених пакетів { #view-currently-layered-packages }

```
rpm-ostree status
```

Ця команда покаже пакети, накладені у вашій системі Bazzite.

## Встановлення файлів RPM { #installing-rpm-files }

Для більшості файлів `.rpm` варто використовувати контейнери Distrobox з Fedora, але іноді їх доводиться встановлювати в хост-систему, якщо в контейнері вони працюють погано.

Встановити файли RPM **у хост-систему** можна за допомогою `rpm-ostree`, ввівши:

```
rpm-ostree install <package>.rpm
```

Можливо, для правильного встановлення доведеться вказати повний шлях (`/path/to/rpmfile.rpm`).

!!! important

    Недолік встановлення локальних файлів RPM не з репозиторіїв Fedora в тому, що оновлення цього пакета не встановлюватимуться автоматично.

## Як додати або видалити репозиторії [COPR](https://copr.fedorainfracloud.org)? { #how-do-i-addremove-copr-repositories }

!!! warning

    Наполегливо радимо по можливості **не** користуватися сторонніми репозиторіями COPR. Пам'ятайте про ризики, зокрема про зламані оновлення, доки репозиторій не буде видалено.

=== "Увімкнення COPR"

    === "DNF5 (Fedora COPR)"

        ```sh
        sudo dnf5 copr enable <USER>/<PROJECT>
        ```

    === "DNF5 (файл репозиторію)"

        Цей спосіб працює не лише з COPR від Fedora, а й з іншими репозиторіями (наприклад, [Docker](https://docs.docker.com/engine/install/fedora/#set-up-the-repository))

        ```sh
        sudo dnf5 config-manager addrepo --from-repofile=https://url/to/file.repo
        ```

    === "Вручну"

        1. Завантажте файл .repo і збережіть його в `/etc/yum.repos.d/`

        2. Потім встановіть пакети за допомогою `rpm-ostree`

        3. Перезавантажте систему

        Якщо під час оновлення системи виникають проблеми з підписами GPG, їх можна виправити, видаливши репозиторій COPR або змінивши у файлі `gpgcheck=1` на `gpgcheck=0` (або схожий параметр) і зберігши його **на власний ризик**.

=== "Вимкнення COPR"

    !!! warning "Спершу обов'язково видаліть усі пакети, встановлені з цього COPR."

    === "DNF5 (Fedora COPR)"

        ```sh
        sudo dnf5 copr disable <USER>/<PROJECT>
        ```

    === "DNF5 (файл репозиторію)"

        Видаліть файл `.repo` з `/etc/yum.repos.d/`

    === "Вручну"

        Видаліть файл `.repo` з `/etc/yum.repos.d/`

## Як відновити репозиторії COPR за замовчуванням { #how-to-restore-default-coprs }

```sh
# Remove all current repos
sudo rm /etc/yum.repos.d/*

# Now copy the default repo files fro /usr/etc to /etc
sudo cp /usr/etc/yum.repos.d/* /etc/yum.repos.d/
```

## **СЕРЙОЗНІ** застереження щодо `rpm-ostree` { #major-caveats-using-rpm-ostree }

Накладання пакетів може мати **серйозні наслідки**, зокрема:

- Призупинити оновлення системи, доки пакети не буде видалено.
- Не дозволити перебазування на інші образи, доки пакети не буде видалено.
- Конфліктувати з пакетами, які вже є в образі, і спричиняти проблеми із залежностями.
- Подовжити завантаження оновлень: що більше пакетів ви накладаєте на систему, то довше.

Накладання пакетів здебільшого призначене для **системних застосунків, бібліотек та інших залежностей**. **Перш ніж** встановлювати програми через `rpm-ostree`, радимо спробувати Flatpak, Homebrew, контейнери, AppImage, Waydroid або запуск версії для Windows через шар сумісності. Тимчасово накласти пакет краще, ніж тримати його накладеним постійно.

## Як видалити **ВСІ** накладені пакети { #how-to-remove-all-layered-packages }

Якщо оновлення не встановлюється через конфлікт накладеного пакета, можна або видалити пакети, що конфліктують, або видалити всі накладені пакети цією **командою**:

```bash
rpm-ostree reset
```

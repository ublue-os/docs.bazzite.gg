# AGENTS.md

## Задача

Этот репозиторий переводится на русский язык через `mkdocs-static-i18n`.

Русские страницы создаются рядом с английскими исходниками по схеме:

```text
src/path/page.md -> src/path/page.ru.md
```

Не переводите `README.md`, если задача явно про документацию сайта. README - для контрибьюторов, а сайт живет в `src/`.

## Что переводить

- В первую очередь переводите страницы, которые есть в `nav` в `mkdocs.yml`.
- Если страница уже имеет `*.ru.md`, не переписывайте ее целиком без причины. Исправляйте точечно.
- Непереведенные страницы можно оставлять английскими: i18n подставит fallback.

## Что сохранять без изменений

- YAML front matter и ключи в нем, кроме человекочитаемых значений вроде `title`.
- Markdown-структуру: заголовки, списки, таблицы, blockquotes.
- MkDocs admonitions: `!!! note`, `!!! warning`, `!!! info` и похожие.
- Tabs вида `=== "KDE Plasma"`.
- Jinja/macro-блоки вида `{% block ... %}` и `{% endblock %}`.
- Code blocks, inline code, команды, пути, имена файлов, имена образов, package names.
- URL, reference labels и anchors, если они используются ссылками.
- UI labels, если это реальные надписи интерфейса: `Settings`, `System`, `Apply`, `Steam Menu`.

## Якоря и ссылки

При переводе заголовков Markdown автоматически меняет anchors. Если исходник или перевод ссылается на старый английский anchor, добавьте явный anchor к переведенному заголовку.

Пример:

```md
## Двойная загрузка с Windows { #dual-booting-windows }
```

Проверяйте ссылки вида:

```md
](#some-anchor)
](./page.md#some-anchor)
```

Не меняйте reference labels без необходимости. Например `[rebasing]: ...` можно оставить как служебное имя ссылки.

## Стиль русского

Это техническая документация, но русский текст не должен звучать как машинный перевод.

Пишите:

- ясно и прямо;
- без канцелярита;
- короткими фразами там, где инструкция простая;
- с нормальными русскими глаголами вместо отглагольных существительных;
- без выдуманных фактов, предупреждений или советов.

Не добавляйте новые факты, цифры, ограничения, исследования или ссылки, если их нет в исходнике или в задаче пользователя.

## Термины

Используйте единые варианты:

- `desktop environment` -> `окружение рабочего стола`
- `Desktop Mode` -> `Desktop Mode`, если это название режима SteamOS/Bazzite
- `Steam Gaming Mode` -> `Steam Gaming Mode`, если это название режима
- `rollback` -> `откат`
- `rebase`, `rebasing` в обычном тексте -> `переход на другой образ`, `переход на другую сборку`, по контексту
- `deployment` в обычных объяснениях -> `состояние системы`; в узких rpm-ostree инструкциях допустимо `развертывание`, если без этого теряется смысл
- `upstream` -> `основной`, `базовый`, `оригинальный`, `актуальный`, по контексту; не оставляйте `upstream` в русской прозе
- `Flatpak remote` -> `репозиторий Flatpak` или `удаленный репозиторий`, если нужно подчеркнуть термин
- `custom image` -> `пользовательский образ` или `собственный образ`
- `host terminal` -> `терминал хост-системы`
- `bootable media` -> `загрузочный носитель`
- `Fast Startup` -> `быстрый запуск (Fast Startup)` при первом упоминании

Названия проектов обычно не переводятся: Bazzite, Fedora Atomic Desktop, KDE Plasma, GNOME, Steam, Flatpak, Distrobox, Waydroid, Homebrew.

## Запрещенные маркеры

В русских переводах избегайте:

- длинного тире `—`; используйте дефис, запятую, двоеточие или перестройте фразу;
- `данный`, `данная`, `данное`;
- избыточного `является`;
- `не только ..., но и ...`;
- `не просто ..., а ...`;
- `Стоит отметить`, `Важно понимать`, `Таким образом`, `В современном мире`;
- английских слов в прозе, если это не команда, UI label, имя проекта или термин, который должен остаться как есть.

## Humanizer-RU

После перевода вычитайте русский текст как редактор.

Цель: не «литературщина», а нормальная техническая речь. Уберите машинные кальки, повторы и гладкие фразы, которые ничего не добавляют.

Хорошо:

```md
Если после обновления система ведет себя странно, откатитесь к предыдущему состоянию через GRUB или `rpm-ostree rollback`.
```

Плохо:

```md
В случае возникновения определенных проблем рекомендуется осуществить откат к предыдущему развертыванию системы.
```

## Проверки

После каждой пачки переводов выполните минимум:

```sh
git diff --check
```

Проверьте русские файлы на маркеры:

```sh
rg '—|[Дд]анный|[Дд]анная|[Дд]анное|\bявляется\b|не только|не просто|Стоит отметить|Важно понимать|Таким образом|В современном мире|upstream|deployment|rebasing|\bremote\b' src -g '*.ru.md'
```

Если `rg` недоступен, используйте доступный поиск или `grep`.

Если в окружении есть зависимости проекта, проверьте сборку:

```sh
just mkdocs build
```

Если сборка не запускается из-за отсутствующего `uv` или других инструментов, честно укажите это в итоговом сообщении.

## Как отчитываться

В конце работы кратко перечислите:

- какие `*.ru.md` добавлены или изменены;
- какие проверки прошли;
- что не удалось проверить и почему.
